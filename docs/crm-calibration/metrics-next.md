# CRM 指标下一轮施工（2026-09-20）

新仓库基线 main `3dedfa0`，来源旧仓库 `7c20bc4f`（#217），旧历史不公开。本轮候选分支 `codex/crm-metrics-next`；提交与 CI 以新仓库 PR 为准，未部署，现役仍使用已验收的 GSV/知识工具。

## 优先级与完成条件

1. **CI 稳定性证据**：worker 的观测失败记录阶段（状态读取/停止原因/RSS/临时目录）和固定类别；原生首购失败断言附带执行回执。保留物理停止与租约释放条件，错误文本、SQL和路径不进入新诊断字段。原失败根因仍未确认，Linux 下一次失败才能进一步取证。
2. **AOV 接入**：`GET /api/v1/metrics/dashboard-purchases` 使用既有认证、日期/渠道过滤，在一次 SQL 聚合内取得 GSV、去重订单、买家及缺口。AOV=看板GSV÷订单数，多行订单只计一次。
3. **AUS 接入**：AUS=同次GSV÷去重买家数，不依赖首购表。未知订单和买家分别返回行数与金额，阻断相应均值；没有用“新客+老客”代替总买家。
4. **真实验收**：代码与合成验证通过后，按授权走审查/发布及服务切换；优先复核已确认的7月1—5日全店窗口，再扩渠道。未部署时新工具应明确不可用，不回退到旧 `AVG(actual_amount)`。

## 口径与待核对边界

- 金额沿用旧看板的过滤和金额舍入；不得再次扣退款。均值按分四舍五入。
- 分母为同过滤范围内源 `order_id`/`user_id` 去重；不改写归档库、不建立猜测身份映射。
- 空集合的GSV为0，AOV/AUS为空并注明无购买。未知标识、空金额和负金额使相应均值不可用。
- 用户追加确认：仅金额为正的有效订单计入AOV分母，有这类订单的买家计入AUS分母；零元订单数与仅零元买家数另列。已确认的部分退款净额原则不覆盖现看板退款标记过滤。
- 数据水位、退款截止日、跨系统身份完整性仍未知；模型只获得聚合，不获得明细、SQL、路径或凭据。
- 当前候选只提供AI查询，不替换旧看板中的客单价/会员溢价显示。
