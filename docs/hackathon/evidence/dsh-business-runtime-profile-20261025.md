# 完整业务 profile 的装配记录

本轮补齐同一候选包中的九插件集合。基线 `0be91ac5` 的预检 artifact `12572311830` 实际只有七个页面插件，缺 CRM 与 Knowledge。新增运行目标 `business-rc3`，发布预检显式选择该目标，来源角色继续为互斥的 `crm/page`。

## 输入与行为

业务 profile 使用现有 `dsh-profile/v1`，包输入使用 `dsh-profile-pack-inputs/v1`。成员按两份锁定来源的原序派生，不维护第三份独立成员清单。生成与准备使用同一 projection，准备时逐字节比较生成文件，再以实际摘要绑定输入。

| Cordis | `4.0.5` |
| 业务 profile | `config/dsh-profile.business.rc3.json` |
| profile SHA-256 | `803129af8aede095119274a5092819c8cd79fa20f33a82cb52bad2aae9ca31f1` |
| CRM 作者 | `21a7368decf3a72f784436880ccb8e597673cae8` |
| 固定组合 artifact | `12571627062`，沿用上一单元已严格读回的字节 |

`--business-profile` 是显式选择。未启用时，原输入和环境回执保持既有行为。启用时，目录、ZIP 和 GitHub 接收路径都传递同一目标，并返回成对运行选择。发布预检的 PR 与手工执行均使用该目标。通用 release loader、接收器、schema 和组合锁没有修改。

两份来源当前没有服务绑定；既有来源绑定拒绝规则保持。不会因装入 CRM 自动增加服务合同，也不会把包验证当作服务准入。
