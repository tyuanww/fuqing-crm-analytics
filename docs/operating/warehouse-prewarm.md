# 分批预热商品与 RFM

先按[隔离实例启动流程](warehouse-runtime-start.md)配置三个 `FQ_WAREHOUSE` 字段和数据库预算。服务与任务使用同一私有状态根目录及聚合缓存，各自持有只读来源连接。任务使用 `prewarm-source` 子目录，不借用服务的连接或目录锁。每种角色只能有一个存活 owner。

先生成计划。此命令仍会重新封存来源，但不计算业务聚合：

```sh
python -m scripts.etl.prewarm_verified_warehouse
```

用有限预算运行第一批：

```sh
python -m scripts.etl.prewarm_verified_warehouse --execute --max-new-results 5 --max-seconds 300
```

重复同一命令继续。任务先按服务的真实调用读取并校验缓存；已有结果不重算，缺失结果才进入顺序计算。每项提交后再用只读模式回读。进程中断后，已提交结果保留，下次重新验证。每次任务独立封存来源，旧报告不能代替当前校验。

`--max-seconds` 在两次计算之间检查，不中断正在执行的 SQL。封存耗时单独记录为 `seal_seconds`，不计入此批预算。内存、线程和 spill 仍受数据库配置约束。不要将批次时限当成单条 SQL 的硬超时。

默认计划覆盖截止日锚定的近 24 个月选项，包含当前及前一年常用周期、完整月、季度和年度。RFM 含八象限及 R/F/M，支持 GSV、GMV、渠道、排除渠道、默认比较和环比。商品只纳入 GSV 且两期各不超过 90 天的选项，不包含 RFM 的长周期。每个商品结果包含完整映射商品，单品筛选复用该结果。用 `--months` 缩小计划，用 `--families product analysis r f m` 选择板块。

RFM 固定周期和自由日期各自保留完整三期语义。固定 WTD 的比较期与第三期不能用相同起止日期的自由查询代替。任务为固定项显式传入离线日历锚点，调用服务后即释放；HTTP 仍按业务当前日解析，不继承任务锚点。R/F/M 的固定周期 HTTP 与八象限服务调用均有回归；八象限当前 HTTP 入口仍要求明确起止日期。

状态根目录的 `prewarm-report.json` 保存计划、逐项结果和摘要，写入通过原子替换完成。`READY` 表示本次按服务调用验证命中，`INSUFFICIENT_COVERAGE` 表示所需日期超出来源范围，`PENDING` 表示未计算，`FAILED` 表示验证或计算失败。出现失败后，本批不启动更多冷计算。报告保留异常类别，不保存异常明细或客户数据。

`expected` 和状态计数是逻辑请求数，周期别名可能共用一个物化结果。`computed` 是本批完成计算及回读的次数。`complete` 仅表示本计划所有支持的请求已验证命中或明确缺覆盖，且至少有一个结果就绪。它不表示任意日期组合均已缓存，也不代表完整前端或真实聊天验收通过。

退出码 `0` 表示计划已生成或执行计划已完成，`3` 表示尚未达到就绪条件，`1` 表示有失败项；参数错误为 `2`。全部请求均缺覆盖时也返回 `3`，即使没有 `PENDING`；此时重跑不会补出缺失数据。检查报告状态后再继续跑数，不从退出码 `0` 的计划生成推断缓存已热。

用 `python -m pytest backend/tests/test_warehouse_prewarm.py` 检查真实合成 SQL、预算停止、跨批恢复、独立 owner、共享落盘缓存与新进程读取。真实仓库覆盖和耗时另行验收。
