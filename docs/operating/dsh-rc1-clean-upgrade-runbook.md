# How to 构建并验收 DSH rc1 干净候选

这份手册用于把 `dsh-v0.2.1-rc.1` 构建成隔离、可回退的候选。它完成切换前检查、profile 装配、plugin-market bundle 与 Discover 入口回读和原生回读；market index、IM artifact、正式门禁和切换授权齐全后，才进入 side-by-side promotion。

## 前置条件

- 固定上游 SHA：`1600d8a1e140dcde43a1a0941940a0480712c011`。
- 构建 Node：`v24.19.0`；插件 pnpm：`11.28.2`；上游 pnpm：`11.28.5`。
- `--portable-linux` 只在 Linux x64 builder 上使用；Mac 或其他平台必须先完成对应平台的本机 bundle 检查，不能把 portable 结果写成已验证。
- 从仓库根目录执行并设置 `DSH_RELEASE_LANE_CONFIG="$PWD/config/dsh-rc1-release-lane.json"`。这是 rc1 lane 的临时输入覆盖，不会修改 `dsh-plugins/plugin-kit/toolchain.json`。
- 候选使用新的 staging root、runtime、profile 和 receipt。旧 runtime 只读保留为回退目标。
- 所有插件从同一 subject set 生成 pack；不得混用旧候选的 profile、tarball 或 generated bytes。

## 步骤

1. 记录 tag、upstream SHA、source SHA、Node/pnpm、插件 pack digest 和回退 runtime。先执行：

   ```bash
   git -C /absolute/pinned/deepseek-harness status --porcelain --untracked-files=no
   git -C /absolute/pinned/deepseek-harness rev-parse HEAD
   ```

   非空工作树或 SHA 不匹配时停止。

2. 使用新的目录构建 production-only runtime：

   ```bash
   node scripts/release/runtime-bundle.mjs \
     --upstream /absolute/pinned/deepseek-harness \
     --output /absolute/staging/runtime-clean.tar.zst \
     --provenance /absolute/staging/runtime-clean.provenance.json \
     --portable-linux
   ```

   构建会物化受支持的 external web-plugin peer alias，拒绝缺失 alias、碰撞、越界 symlink、host path、AppleDouble 文件和 secret。`pnpm deploy --prod` 成功本身不够，必须看到 runtime provenance `PASS`。

3. 生成或读取 profile-pack inputs。profile 至少包含 DSH base、web app、7 个内置业务插件和官方 plugin-market bundle。插件 pack reader 要求 `dsh-generated-bytes/v1`，且 source tree、generated tree、builder identity 和 tarball digest 来自同一候选。

4. 运行 profile 检查和 native boot：

   先确认隔离 web 端口 `14327` 空闲；`cli.mjs` 遇到占用会直接失败，不会停止其他候选。

   ```bash
   node scripts/dsh-dev/cli.mjs check \
     --plugin on \
     --upstream /absolute/pinned/deepseek-harness \
     --pack-inputs /absolute/staging/profile-pack-inputs.json \
     --runtime /absolute/staging/runtime-check

   node scripts/dsh-dev/cli.mjs start \
     --plugin on \
     --upstream /absolute/pinned/deepseek-harness \
     --pack-inputs /absolute/staging/profile-pack-inputs.json \
     --runtime /absolute/staging/runtime-check \
     --web-port 14327 \
     --page-http on \
     --page-http-port 18125 \
     --detach
   ```

5. 在候选自己的浏览器或 SSH tunnel 中回读：未认证 `GET /` 为 `401`；启动 token 只能一次兑换 HttpOnly cookie；插件页、Settings、登录回调、会话入口和 plugin market Discover 均可打开。记录控制台结果，不能把未采集写成无错误。

6. 运行候选专用的负测和回归：

   ```bash
   node --test scripts/release/release.test.mjs
   git diff --check
   ```

   新增的 peer alias 负测必须覆盖缺 `dsh-tools` 时的 `RUNTIME_EXTERNAL_WEB_PLUGIN_PEER_MISSING`。本机 Node 25 造成的环境失败要单独记录，不能改测试或假报绿色。

7. 写 `candidate-profile-receipt.json`。候选回执至少记录 `candidate_tag`、`upstream_sha`、runtime/profile SHA、plugin-market bundle、每项检查、IM 状态、`release_ready`、当前线上 symlink 和候选端口。进入 promotion 前，再把 source identity、Node/pnpm、pack digests、正式 runtime provenance 和明确 fallback target 从同一 subject set / owner receipt 绑定到 activation journal；只有候选回执本身不够。

8. 只有以下条件全部满足才准备 side-by-side promotion：IM package/index 已由归档输入提供；正式 publisher、signature、independent verification、revocation、final attestation 和 clean-machine 门禁齐全；候选 receipt 与 activation journal 绑定同一 digest；用户已明确授权切换。候选阶段不改线上 `current`。

9. 切换后保留旧 release，先验证 service active、`401` 认证边界、浏览器插件页、登录和原生会话，再进行真实业务 UAT。任何失败都只停候选并把 `current` 指回已验证旧 release；不要覆盖旧目录，也不要用 `git pull` 在服务器重建。

## 验证

本次 v4 候选的可复核结果：candidate tag `dsh-0.2.1-rc.1-clean-main-20261020-v4`，runtime SHA-256 `d3d504dd39cd333fb98acf61cf4597664f6d4fda5482fb2ea970748bd2b8a94f`，profile SHA-256 `c3ec7df313c2323996428b1034af0fd5eec5fffe1d06a8c618532074110503ad`，plugin-market Discover、native boot、settings/account RPC、peer negative test 和 v4 boot 均通过，AppleDouble locale 文件为 `0`，控制台日志为空。

当前生产 symlink 仍为 `/srv/shinemage/dsh/releases/dsh-0.2.1-rc.1-owner-main-4ac076de-20261019`，服务为 active。IM 状态为 `BLOCKED_MISSING_ARTIFACT`，所以 production switch 为 `HELD_PENDING_IM_ARTIFACT`，`release_ready=false`。

## 排障

| 现象 | 处理 |
|---|---|
| `ERR_MODULE_NOT_FOUND` 指向 `@deepseek-ai/dsh-*` | 检查 runtime peer alias root 和 profile bridge；重新构建候选，不能从任意 host checkout 链接。 |
| `RUNTIME_EXTERNAL_WEB_PLUGIN_PEER_MISSING` | 固定上游没有提供显式 alias。停止候选，更新上游/profile 输入后重新构建。 |
| `._en.json` 或其他 AppleDouble 文件出现 | 删除 staging，确认打包输入来自干净 Linux/归档树，再重新构建。不要在已生成 bundle 上打补丁。 |
| 插件市场页面存在但 Discover 为空 | 检查 profile 是否包含官方 market bundle 及其 index；不要把旧市场目录复制进新 runtime。 |
| 登录后白屏 | 先看 `401 → 一次性 token → HttpOnly cookie → 200` 链路，再查候选 runtime/profile；不要关闭认证或复用旧 cookie。 |
| IM 缺包 | 保持 `release_ready=false` 和 `HELD_PENDING_IM_ARTIFACT`，等待已归档、可校验的 IM 输入。 |
