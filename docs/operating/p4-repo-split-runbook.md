## 6. Failure and rollback

**Abort any slice before its commit lands if:** author CI is red or its run head ≠ the pinned sha; `KIT-SHA256` ≠ `sha256sum vendor/*.tgz`; a formal-pack digest ≠ the lock; `SOURCE_MANIFEST_*`/`BOUNDARY_OWNER_STALE`/`RELEASE_PACK_*` throws; `respin --check` reports drift; an author artifact has expired; or b0/preflight is red.

**Rollback is a revert, never an edit.** Each slice lands as its own commit, so:

```bash
git revert --no-edit <deletion-commit>          # restore sources for that slice
# if a repin commit landed after it, revert that first, then the deletion:
git revert --no-edit <repin-commit> <deletion-commit>
git status --short                              # must be empty
node scripts/dsh-b0/plugin-boundaries.mjs --check
node scripts/dsh-b0/pipeline.mjs --check        # b0 green is the rollback proof
node scripts/release/respin-composition-artifact.mjs --check   # RESPIN_CHECK_OK
sha256sum config/shinemage-composition-packs.lock.json config/shinemage-composition-artifact.lock.json
```

Rollback proof must show: the restored `dsh-plugins/` inventory matches the pre-deletion tree (`git show <pre>:dsh-plugins` vs `ls`), the lock digests equal their pre-deletion values, the sealed artifact `id/sha256/runId/headSha` is unchanged (`13385901661` / `3865e362…` / `41961810401` / `5e4510b3…`), and b0 is green. If only a lock was wrong, revert the lock; never hand-edit `.ci`, never `--force` the sealing branch, and never re-run the ACP cutover as a rollback.
