# DSH plugin pack and provenance reference

This reference describes the package boundary used by the release packer and reader. It applies to an independent plugin pack. It does not grant activation or production release permission.

## Pack receipt

The pack receipt uses `dsh-plugin-pack/v1` and contains:

| Field | Meaning |
| --- | --- |
| `package_name` | The `@shine-mage/*` package name |
| `package_version` | The package version |
| `dsh_pin` | The exact `@deepseek-ai/dsh-tools` peer version for a tool plugin |
| `source_sha` | The clean plugin repository commit |
| `source_dirty` | Must be `false` |
| `tarball.name` | The generated `.tgz` filename |
| `tarball.bytes` | The tarball byte count |
| `tarball.sha256` | The tarball digest |
| `entries` | The final archive entries |
| `generated_bytes_provenance` | The source, generated bytes, builder, and receipt binding |
| `activation` | `NOT_RUN` for a plugin-only pack |

The archive may contain declared runtime files and `package.json`. It must not contain source files, tests, `node_modules`, source maps, symlinks, workspace links, credentials, or undeclared files.

## Manifest digest names

The repository uses explicit field names when one artifact has multiple manifest digests:

| Field | Byte source |
| --- | --- |
| `source_package_manifest_sha256` | The plugin source `package.json` |
| `generated_pack_manifest_sha256` | The generated `plugin-pack.json` receipt |
| `tarball.sha256` | The final `.tgz` archive |

These values are not interchangeable. A source manifest can stay unchanged while generated provenance changes, or a generated manifest can stay unchanged while a tarball differs. Consumers must use the named field rather than an unqualified `manifest_sha256`.

## Configuration bundles

A pure configuration bundle sets `shinemage.bundle_role` to `configuration-bundle`. It may omit the `@deepseek-ai/dsh-tools` peer because it contributes DSH patch/configuration rather than tool implementation. The same package must not declare that module in `dependencies`, `optionalDependencies`, `devDependencies`, or `peerDependencies`, and packaged `.js/.mjs/.cjs` files must not import it through static, dynamic, concatenated, or computed module loading. Runtime work still belongs in an independently installed tool plugin.

For package `files` and both sides of `exports`, one `*` may match immediate files in one fixed directory, such as `locale/*.json`. Multiple stars, a wildcard in the directory portion, recursive matching, path escape, and symlinked matches are rejected. A wildcard export target is accepted only when its containing export key also contains `*`; a wildcard value under an exact key is rejected. A wildcard must match at least one regular file before packing. `main`, `module` and `dsh.bundle.patch` must name exact files and cannot use a wildcard.

The optional `shinemage.composition_contract` value is an exact compatibility discriminator consumed by profile assembly. For example, `crm-knowledge-split/v1` identifies packages admitted to that composition, and a differing value is rejected. It is neither a release identity nor a substitute for the source, pack, or tarball digests.

## Generated bytes provenance

`generated_bytes_provenance` uses `dsh-generated-bytes/v1`. A clean builder receipt is read from `dsh-plugin-build/v1` and normalized into this generated-bytes schema.

The binding covers:

```text
source git SHA
  + source tree digest
  + generated tree digest
  + builder status, clean flag, isolation flag, Node, pnpm
  + builder receipt SHA
  + final tarball name, byte count, and SHA-256
```

The reader compares every digest with the bytes it receives. It rejects a changed ignored `lib/`, a dirty source tree, a different builder toolchain, a missing receipt, or a tarball digest mismatch.

## Reader contract

Use `readPluginPack` with `requireGeneratedProvenance: true` for a formal candidate or release path. The reader also checks the DSH peer, package manager, archive root, package manifest, entrypoints, declared files, activation scope, and maximum archive size.

The controlled packer is invoked with absolute paths:

```bash
node scripts/release/plugin-pack.mjs \
  --plugin /absolute/plugin \
  --output-dir /absolute/output \
  --manifest /absolute/output/plugin-pack.json \
  --builder-receipt /absolute/plugin/.build-provenance.json
```

The packer does not build DSH, start a host, upload a package, activate a plugin, or create a release journal entry. Candidate admission and host activation belong to separate commands.

## Error codes

| Error | Meaning | Next action |
| --- | --- | --- |
| `PLUGIN_PACK_BUILD_PROVENANCE_REQUIRED` | The formal path has no builder receipt | Build the plugin in a clean isolated workspace and write the receipt |
| `PLUGIN_PACK_SOURCE_TREE_MISMATCH` | The source tree changed after the receipt | Rebuild from the exact source commit |
| `PLUGIN_PACK_GENERATED_TREE_MISMATCH` | Generated bytes changed after the receipt | Remove the ignored output and rebuild |
| `PLUGIN_PACK_SOURCE_DIRTY` | The plugin checkout has tracked or untracked changes | Clean the plugin checkout before packaging |
| `PLUGIN_PACK_WORKSPACE_LINK` | The package depends on a workspace or file link | Publish or pin the dependency for the pack |
| `PLUGIN_PACK_TARBALL_UNDECLARED` | The archive contains an undeclared file | Update the package `files` allowlist only when the file is a real runtime entry |
| `PLUGIN_PACK_CONFIGURATION_BUNDLE_TOOL_DEPENDENCY` | A configuration bundle declares `@deepseek-ai/dsh-tools` in a dependency field | Move tool implementation to a tool plugin and remove the dependency |
| `PLUGIN_PACK_CONFIGURATION_BUNDLE_TOOL_IMPORT` | A packaged configuration file imports `@deepseek-ai/dsh-tools` | Remove the import; configuration bundles may not carry tool implementation |
| `PLUGIN_PACK_CONFIGURATION_BUNDLE_DYNAMIC_MODULE_LOAD` | A packaged configuration file uses `import()` or `require()` | Remove runtime module loading; configuration bundles may not carry executable module resolution |

## Scope limits

A passing pack proves package bytes and provenance. It does not prove host compatibility, browser behavior, service compatibility, real data access, target recovery, company verification, signing, revocation, or production activation.
